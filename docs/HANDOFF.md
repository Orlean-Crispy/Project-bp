## 1. 这一段（S60 → S63）做完了什么

### 1.1 治理：从"靠人记住"到"靠结构错不了"

起因是外部审计的一句话：协议位域只剩 1 个 bit 而 M6 要 6 个新位——**不是代码 bug，是没人记账**。
于是照"账实相符制"搭了六件东西：`STATE`（现在）、`budgets`（有限资源）、`contracts/M6`（里程碑合同）、
`DEBT`（债，状态四值 + 每条带 verify）、`BACKLOG`（设计待定/功能缺口）、`tools/doc_check.py`（防漂移闸门）。
S01–S59 的 HANDOFF、GAPS、AUDIT、8.3 专章都归档了；HANDOFF 这个**形态**保留下来，
但只写叙事（见本文开头），数字仍然只在 STATE。AGENTS 只留指针——"17 项闸门"这类数字从五个文件收到一处。

**doc_check 不是装饰**：它有 `--selftest`（在故意写坏的树上必须报错），而且上线当天就抓到了四处真实漂移
（AGENTS 指向已归档的 HANDOFF、README 的 4.7/4.5 自相矛盾、新写的 PROGRESS 引用了还没建的文件、
STATE 里 `2.40 / 4.20` 被正则当成闸门计数）。

### 1.2 审计的 7 条进入条件：全部落地，每条都有自己的闸门

协议位域扩容（mask/flags 宽了一倍，带 Vitals 真值与 Weapon 预留）、分片接真实链路、UDP 源地址校验、槽位释放、
落后补 tick + 本地渲染插值、E 键让给交互、腿倍率进 toml。细节与实测输出在 `docs/contracts/M6.md` §1。

### 1.3 代码体检：拆、去重、删死代码

原来的 `tests_net.cpp` 有 81 KB。按主题拆成 `tests_net`（会话）/ `tests_transport`（UDP+分片）/
`tests_lobby`（准入+票据+组局）；删掉与协议闸门重复的 `[snapfields]`；
两份逐字相同的轮询 lambda 收成一个 `wait_for()`（其余等待循环各按需要内联，没有强行统一）；
槽位释放从"队列 + 记得 drain"改成回调；补 tick 与加入共用 `advance_to_clock()`；
`UdpTransport` 删掉只有测试用的 `recv_from/adopt_peer`；`ClientId` 独立成头。
顺手修了一个真 bug：首帧相机从世界原点滑向出生点（"上一 tick 位置"没初始化）。

### 1.4 M6：三条设计决定落地，然后停在第一个小任务上

ADR 0006 定下穿透（武器决定/地图否决）、护甲（按部位：爆头真伤）、热重载（不做，记债）。
护甲规则当场写成代码（`apply_damage(vitals, damage, zone, params)`）。
M6 拆成 M6.0–M6.12，**一次只做一个**；M6.0 已完成，M6.1 还没开始。

## 2. 决定与理由（为什么是现在这个样子）

| 决定 | 理由 | 被否掉的替代方案 |
|---|---|---|
| 协议位域一次扩到 16 位，并**预留** Weapon 组（恒 0） | 扩位是半天到一天的活；M6 中途改协议要连带动 demo、闸门基线、桥接口 | 只扩位不加组 → M6 加武器还要升 v7；等 M6 再扩 → 返工一周 |
| 分片在**真实链路**两侧都挂上，而不是只在闸门里 | 满编快照已经逼近分片阈值（具体数看 `budgets`）；IP 分片丢一片整帧报废 | 等超了再挂 → 那时问题表现为"偶发瞬移"，最难查 |
| 槽位释放用**回调**而不是队列 | 队列要求每个调用方都记得 drain，`net_loop` 第一天就漏了；回调装一次就不会漏 | 保留队列 + 给 net_loop 补 drain（同类泄漏还会有下一次） |
| 护甲按**部位**结算，爆头真伤 | 让"瞄准"有独立价值：护甲不再是第二管血 | 66% 吸收（原提案）→ 爆头被护甲稀释，精准的价值被摊平 |
| 热重载**不做**，文档改成"启动时读" | 改 toml 不需要重编、只需重启（几秒）；真正要反复调的是还没建的武器表 | 现在补 `reload()` → 只覆盖 movement，M6.1 后还要改同一个函数 |
| M6 拆成 13 个（M6.0–M6.12），一次一个 | 一口气做完会让"哪一步坏了"无法定位；M6 恰好是引入最多新状态的阶段 | 按 W1–W9 一次推进（原契约）→ 中途失败只能整体回退 |

## 3. 现在的结构（只讲形状，数字看 STATE）

- **一条数据流**：`godot/main.gd`（读输入、驱动 tick、摆相机）→ `bridge/sim_bridge.cpp`（唯一跨边界层）
  → `sim/`（纯 C++17，零 Godot 依赖）→ 快照/事件回桥。sim 永远不知道 Godot 存在。
- **两条跨边界通道**：状态流（快照）与事件通道（`EventQueue`，1024 固定环）。伤害只走快照，不走事件。
- **三个"单一来源"**：端口只在 `sim/net/ports.h`；版本只在 `sim/core/version.h`；
  sim 源文件只在 `tools/sim_sources.txt`（`check_sources.ps1` 卡住）。
- **测试按主题分五份**：`tests_move`（pmove/碰撞/键位/血量）、`tests_net`（会话同步）、
  `tests_transport`（UDP/分片）、`tests_lobby`（准入/票据/组局）、`tests_proto`（线格式）。
  单文件上限 70 KB 是 `budgets` 里的一行（当前最大的是 `tests_move`，56 KB）。

## 4. 这一段踩到的坑（根因 + 怎么发现的）

1. **协议字段改了宽度，但写入还是旧的**：encode 里 `w.u8(now.flags)` 忘了改成 u16，0x7FF 被截成 0xFF。
   新加的 `--test-snapshot` 第一次运行就红了——**这就是"先写闸门再实现"的价值**。
2. **同一份判据写两遍**：`--test-net` 的 `[snapfields]` 与 `--test-snapshot` 是同一件事。
   两份实现迟早给出两个答案；删掉旧的那份。
3. **队列式回调**：`drain_departed` 需要一个"记得调用"的调用方。`net_loop` 忘了，槽位就泄漏。
   改成回调后这类 bug 在结构上消失。
4. **测试自己写错，看起来像产品 bug**：`[slots]` 第一版 `cycles 0/0`，原因是测试忘了释放
   上一轮占用的 id。**闸门红了先怀疑闸门**，但不要为了让闸门变绿去改产品。
5. **LoopbackTransport 会把积压都留着**：冻结客户端 300 tick 后，恢复时把 300 份快照逐份解完就"追上"了，
   `behind` 只有 5。真实 UDP 缓冲区不会留 4.7 秒——补上"丢积压"这一步才复现出 `behind 293`。
   **测试环境与真实环境的差异，要么建模要么显式丢掉。**
6. **改键会撞测试**：爬墙从 E 改到 V 后，键位测试里"把 jump 重绑到 V"就与爬墙冲突。
   换到 Z，并补一条"E 不许被任何移动动作占用"的断言。
7. **拆分测试文件后 include 缺一整组**：`tests_lobby` 少了 `ports/session/transport` 三个头，
   -Werror 一次报出一串未声明符号（连着级联）——**这类错误编译器比人可靠**。
8. **文档正则抓错目标**：doc_check 用"第一个 `N/N`"当闸门数，被 STATE 里 `2.40 / 4.20` 抢先命中。
   改成只认 `smoke … N 项`。**闸门自己也会误报，误报要修闸门，不是改文档去迎合它。**
9. **首帧相机滑入**：`get_prev_position()` 在第一次 step 之前是 (0,0,0)，插值把相机从世界原点拉过来。
   `load_map` 末尾先记一次"上一 tick"。**任何"历史"数组都要有初始化点。**
