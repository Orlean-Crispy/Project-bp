# 5. 眼高落在头段里：平射全是爆头

**日期**：2026-10-24（DESIGN-09/10）

## 症状

验收时 TTK 表显示躯干 0.28 s，比设计目标 0.6–1.2 s 快一倍多；但更奇怪的是
打起来的感受 —— 对枪经常一瞬间结束，回放里几乎每一发都是 125（爆头）。

## 原因

相机和弹道都从**眼高**出发。眼高是 `0.9 × 身高 = 1.278 m`，而头段的起点是
`0.82 × 身高 = 1.164 m`。也就是说：**水平瞄准同身高对手的胸口，射线正好从眼睛高度飞过去**，
而眼睛在头段里面。

结果：瞄准最自然的姿势（平视）永远是爆头，1 发 125 伤害。伤害模型、护甲、距离衰减
全都没机会生效 —— **几何静默地废掉了整个数值设计**。

## 为什么难发现

- 每一层单独看都合理：眼高 0.9 是常见值，头段 0.82 是常见值。
- 命中判定测试是"打在指定高度上 → 得到指定部位"，从来不问"玩家会怎么瞄"。
- `--test-health` 的爆头测试直接调用 `apply_damage(..., Head, ...)`，绕过了几何。

## 修法

把两个数**放进数据**并规定一条不等式：

```toml
[base]
eye_height_scale = 0.82   # 1.164 m
[damage]
head_band = 0.88          # 1.25 m，必须 > eye_height_scale + 0.05
```

闸门直接钉这条规则（`--test-hitbox`）：

```
a level shot is a body shot, not a headshot   ok
```

## 判据

- `hit_zone_at(stand, eye_height_scale * height, params) == Chest`
- `eye_height_scale + 0.05 < head_band`

## 教训

**调整伤害模型之前，先问"玩家默认怎么瞄"。** 一条水平射线穿过人形盒时落在哪一段，
是玩法问题，不是碰撞问题；把它写进闸门，比在文档里写"注意"有用。
