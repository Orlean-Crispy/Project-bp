# §8.3 候选 B 深化设计（v0.4 草案）

> **插入位置**：§8.3 之后，作为 §8.3.1 – §8.3.9
> **状态**：设计草案，未验证。数值全部为待调初值
> **前提**：已采纳 §5.7 的 `climbable` / `wallrunnable` 默认 0
> **约束来源**：§5.6 玩家尺寸、§8.3 C3 时间算法、§8.5 垂直预算、§5.9 最小墙厚

---

## 8.3.1 重新定义「进入方式」

原稿写的是：

```
进入方式 = 破窗/破地板（不是爬墙）
破坏有声音代价
```

**问题**：这句话隐含了一个二值判断——「能进 / 不能进」。一旦二值化，地图上每个点就只有两种命运：要么有一条常规路（破坏成了纯加速，可有可无），要么没有常规路（破坏成了唯一解，每回合流程固定）。

两种都会退化。CS 之所以二十年版图稳定，是因为入口是**多条的、且每条代价不同**。

**改法**：

> **破坏不决定「能不能进」，只决定「用什么代价进」。**
> 每个目标点必须有 ≥2 条常规入口；破坏提供的是**第 3、4 条入口**，
> 它们换来的不是「通路」，而是「时间」——并为此支付「声音 + 暴露 + 装备槽」。

这样破坏才是博弈，而不是流程。

---

## 8.3.2 破坏的三层代价

| 层 | 内容 | 可调参数 | 设计作用 |
|---|---|---|---|
| **时间** | 布置 + 引信 + 落位 | 总秒数 | 决定它值不值得用 |
| **声音** | 半径 × 材质 × 楼层滤波 | 半径表 | 决定谁会被惊动 |
| **资源** | 装备槽 / 每回合次数 | 预算 | 决定能滥用几次 |

三层的功能不同，缺一不可：

- 只有时间 → 破坏必用（免费加速）
- 只有声音 → 破坏滥用（听得到但拦不住）
- 只有资源 → 破坏变成「攒着不用」（怕浪费）

**关键**：声音是**局部**的，不是全图广播。这一点和 CS 拆包声（全图可闻）不同，更接近 R6 打洞。破坏因此是一种「局部信息交易」：用附近所有人的注意力，换一条局部通路。

## 8.3.3 破坏档位（与玩家胶囊尺寸绑定）

这是候选 B 最该先定的一张表。取 **chunk = 0.5 m**，与 §5.6 的玩家尺寸对齐：

| 玩家尺寸 | 值 |
|---|---|
| 盒宽 | 0.81 m |
| 蹲高 | 0.91 m |
| 站高 | 1.42 m |
| 台阶 | 0.46 m |

于是 0.5 m 的网格天然切出**四个战术档位**：

| 档位 | chunk | 实际开口 | 余量 | 能做什么 |
|---|---|---|---|---|
| **观察孔** | 1×1 | 0.5 × 0.5 | — | 能看、能穿弹、人过不去 |
| **射击孔** | 2×1 | 1.0 × 0.5 | — | 横着架枪，**人过不去** |
| **蹲行** | 2×2 | 1.0 × 1.0 | 宽 0.19 m | 蹲着勉强挤过 |
| **站立通行** | 3×3 | 1.5 × 1.5 | 宽 0.69 m | 直接跑过 |

**这张表是整个候选 B 的地基。** 它意味着：

1. 破坏不是「破开 / 没破开」，是**四档渐进**，中间两档（观察孔、射击孔）提供了「获得信息但不获得通路」的博弈状态——这是 CS 的门做不到的
2. 进攻方可以**故意只破到射击孔**，制造「我要打这里」的假象，实际转点。假动作不需要任何道具，成本就是几发子弹
3. 防守方看到射击孔时，面对的是「他可能从这里打，也可能已经转点」，而不是「门开了」
4. 洞口的通过成本直接绑到移动系统：**站立的洞 3×3 可以直接跑过，蹲行的洞 2×2 要减速**，高处的洞要花 1 次 impulse 才能上去（见 8.3.5）

> **为什么是 0.5 m 而不是 0.25 m**：0.25 m 会让「站立通行」变成 6×5 = 30 块，破坏手感碎成渣；1.0 m 则只有「过 / 不过」两档，丢掉中间态。0.5 m 刚好落在「四档、每档都有意义」的区间里。

## 8.3.4 材质 × 手段矩阵

破坏手段必须按材质分层，否则「顺手打两枪就破墙」会让整套代价模型失效。

| 材质 | 步枪/手枪 | 霰弹 | 破门锤 | C4 | 声音半径 | 可否加固 |
|---|---|---|---|---|---|---|
| 玻璃 | 1–2 发全碎 | 1 发 | 碎 | 碎 | 10 m | ❌ |
| 木板 | 可穿弹，命中累积 | 1 块 / 发 | 1 块 / 击 | 3×3 | 15 m | ❌ |
| 混凝土 | **无效** | 1 块 / 2 发 | 1 块 / 击（1.2 s） | **3×3 一次** | 45 m | ✅ |
| 加固混凝土 | 无效 | 无效 | 无效 | 1 块 / 次 | 30 m | — |

**核心决定：普通子弹对混凝土无效。**

理由：
- 如果子弹能打穿承重墙，「混凝土」和「木板」的差别就只剩血量，材质表退化成一张数值表
- 「无效」让破坏成为**必须专门准备**的动作，从而能挂上装备槽和回合预算
- 与 §5.7 的 `penetrable` 字段天然一致：能穿弹的必然能破，能破的不一定能穿弹

由此，每回合的破坏能力大约是：

| 手段 | 可完成的档位 | 耗时 |
|---|---|---|
| C4 | 3×3 站立通行 | 布置 1.5 s + 引信 2.0 s = **3.5 s** |
| 破门锤 | 2×2 蹲行（4 块 × 1.2 s） | **4.8 s** |
| 霰弹枪 | 2×1 射击孔 | 约 2 s |
| 步枪 | 1×1 观察孔（仅玻璃/木板） | < 1 s |

**结论**：C4 是唯一能开「站立通道」的手段，破门锤是「精细雕刻」，枪械只能做「信息型破坏」。三者不重复，各有自己的战术位置。

## 8.3.5 时间预算规则（候选 B 的核心约束）

§8.3 C3 已经给了机动优势的算法：

```
1. 纯跑 A → B          例：8 s
2. 全程 parkour A → B  例：5 s
3. 差值 = 允许的机动优势  3 s
4. 调 impulse 上限，使最大收益 ≈ 3 s
```

候选 B 必须补上另一半：

> **破坏的净时间收益，必须 ≤ 机动优势 × 1.5**

```c
// 净收益
T_gain = T_常规路径 - (T_到位 + T_破坏 + T_落位)

// 硬约束
assert(T_gain <= T_parkour_gain * 1.5f);
```

代入示例图：

| 项 | 秒 |
|---|---|
| T 常规路径（走楼梯到 B） | 18.0 |
| T_到位（跑到 B 下方） | 10.0 |
| T_破坏（C4 3.5 s） | 3.5 |
| T_落位（破天花板后落入 B） | 1.5 |
| **T_gain** | **3.0** ✅ |

**为什么乘 1.5 而不是 1.0**：破坏次数被「每回合 2 次」卡死，是稀缺资源；parkour 是无限次的。稀缺资源单次收益略高是合理的。但不能高太多——一旦超过 1.5 倍，「练 parkour」就会被「等 C4」取代，移动系统的深度白做。

**为什么不能低**：低于 0.5 倍就没人用了，3 个可破坏面会变成装饰。

这条约束是候选 B 与 §8.3 C3 的**闭环**：C3 定 parkour 的上限，本条定破坏的上限，两者共同决定 impulse 数值。

## 8.3.6 每张图的破坏预算

| 项 | 规定 | 理由 |
|---|---|---|
| 可破坏面总数 | **3 处**（2 墙 + 1 地板/天花板） | 超过 3 处地图结构会崩 |
| 每回合破坏上限 | **2 处 / 队**（共享计数） | 防止「全部破开」退化成开阔场地 |
| 加固 | 防守方准备阶段 **1 处 / 回合** | 攻防对称，见 8.3.7 |
| 可破坏面位置 | 禁止在出生点 15 m 内 | 等于白送 |

**必须有天花板/地板面**：只做「墙」等于浪费了 §8.5 的 2.5 层设计。垂直破坏是候选 B 相对传统 CS 图唯一的独有维度，它带来的「从上方垂降」和「从下方突入」是平面图给不了的。

## 8.3.7 防守方反制：极简加固

**没有加固，可破坏系统长期必然失衡**：每回合 2 次破坏 × 无限回合 = 进攻方单方面收益，防守方只能被动接。

v0.1 的极简版：

```
准备阶段 8 秒，防守方对 1 处可破坏面加固
加固后：混凝土 → 需 C4（枪/锤彻底无效），血量 ×2
加固面同样占用「可破坏面」计数
```

它带来的博弈正是 R6 的骨架：

- 防守方先选「守哪面」，进攻方后选「破哪面」
- 但防守方不知道进攻方打 A 还是 B，加固本身就是一次信息下注
- 进攻方看到加固，就知道「这面墙要花双倍代价」，可能转向另一面
- **8 秒准备阶段 = 防守方的信息优势期**，和 CS 的「先到点位」是同一个功能

> 完整版（可拆除、可重复加固、加固材料经济）留到 v0.3 之后。v0.1 只要有「1 处 / 回合」就够跑通博弈。

## 8.3.8 技术约束（写死，违反会出 bug）

| # | 约束 | 原因 |
|---|---|---|
| 1 | **chunk 深度 = 墙厚**，禁止在墙厚方向分层 | 否则破一半会留下 0.05 m 薄片，直接违反 §5.9 的 `MIN_WALL_THICKNESS = 0.15 m`，20 m/s 滑铲会穿过去 |
| 2 | 可破坏面必须是**独立 brush 组**，不与静态几何合并 | func_godot 生成时若合批，删除会连带 |
| 3 | 客户端**不预测**破坏后的碰撞 | 预测穿墙后被拉回，比「等一下」更难受。局域网 1–2 tick，感知不到 |
| 4 | 破坏状态 = **位图**，每面 ≤ 64 bit，全局 ≤ 16 面 | 快照里 8 字节/面，整图 24 字节，可忽略 |
| 5 | 破坏是**服务器权威 + 事件驱动**，不是每帧状态 | 走 §3.4 的事件通道：`EV_BREAK(面 id, 材质, 位置, chunk 索引)` |
| 6 | 回合重置 = **位图清零**，不重建数据结构 | 遵循 §3.5「不析构重建」 |
| 7 | 破坏声必须走 §9.2 的**楼层低通滤波** | 否则二层破墙和一层破墙听起来一样，垂直信息全部丢失 |
| 8 | 洞口的「可通行性」由**扫掠检测实时判定**，不用预设标记 | 3×3 洞若被碎块挡住，应判定不可过，而不是靠 `passable` 字段说谎 |

**关于第 1 条的量化**：chunk = 0.5 m、墙厚 0.25 m 时，一块 chunk 是 0.5 × 0.5 × 0.25 的凸体。破坏 = 从 brush 列表里移除这个凸体。移除后相邻 chunk 的侧面成为新的墙面，法线仍是轴对齐的——**这就是 chunk 方案相对体素的唯一优势：破坏后永远不会产生非轴对齐的斜面或薄片，墙跑、滑铲的法线判定全部保持稳定。**

## 8.3.9 反模式清单（写进评审，防止日后重犯）

| 反模式 | 后果 |
|---|---|
| ~~全图可破坏~~ | 变成拆迁模拟器，点位失去意义，防守方无处可守 |
| ~~破坏无次数上限~~ | 一回合开 6 个洞，地图结构在 2 分钟内崩解 |
| ~~破坏不发声~~ | 变成无代价作弊，攻防完全不对称 |
| ~~破坏后不可修复~~ | 长回合（>90 s）防守方必输，节奏断裂 |
| ~~只做墙面，不做天花板/地板~~ | 浪费立体设计，候选 B 退化成候选 A |
| ~~破墙用子弹即可~~ | 材质表退化成数值表，装备槽和预算全部失效 |
| ~~洞口靠预设 `passable` 标记~~ | 碎块挡路时会出现「明明能过却过不去」的判定 bug |
| ~~破坏点设在防守方出生点旁~~ | 等于白送一个入口，防守方没有反应窗口 |

## 8.3.11 地图结构示例（80×80 m，5v5）

```
                        ┌──────────────┐
                        │  屋顶高点     │ ← 只能从 B 二层跳上（单向，下来回不去）
                        └──────┬───────┘
        ┌──────────────────────┴───────────────────────┐
        │  2F：B 点                                     │
        │   ┌─────────┐        ┌──────────┐            │
        │   │  机房    │        │  B 点台  │            │
        │   └─────────┘        └──────────┘            │
        │        ↑ 外墙玻璃（可破，10 m 声）             │
        ├──────────────────────────────────────────────┤
        │        ↑ 楼板东段（可破，C4，45 m 声）          │
        │  1F：A 点                                     │
        │   ┌─────────┐                                 │
        │   │  A 点   │ ← 主入口 ×2（正门 / 侧廊）        │
        │   └─────────┘                                 │
        └──────────────────────────────────────────────┘
                 ↑ T 出生点（南）
                 D 出生点（北，A 与 B 之间）
```

**路径时间表**（用于 §8.3 C3 与 8.3.5 的核算）：

| 路线 | 时间 | 备注 |
|---|---|---|
| T → A 正门 | 12 s | 常规 |
| T → A 侧廊 | 14 s | 常规，绕后 |
| T → B 楼梯 | 18 s | 常规，唯一楼梯 |
| T → B 楼板下方 | 10 s | 破坏前置 |
| C4 布置 + 引信 | 3.5 s | — |
| 落入 B | 1.5 s | — |
| **破坏路径合计** | **15.0 s** | **净赚 3.0 s** ✅ |
| T → B 外墙 | 9 s | 玻璃，10 m 声 |
| 破玻璃 | 0.5 s | — |
| 翻入 | 2.0 s（消耗 1 次 impulse） | — |
| **玻璃路径合计** | **11.5 s** | **净赚 6.5 s** ⚠️ 需调 |

> **⚠️ 玻璃路径超限**：6.5 s > 3.0 × 1.5 = 4.5 s。
> 调整：把外墙位置移到 B 点背面（T 需绕行 4 s），或把翻入高度提到 1.22 m 以上（强制 2 次 impulse）。
> **这条正好演示了 8.3.5 的约束怎么用**——先算表，再改图，不要靠感觉。

**旋转时间**（防守方）：

| 路线 | 时间 |
|---|---|
| A ↔ B 纯跑（走楼梯） | 8 s |
| A ↔ B parkour（墙跑 + 跳） | 5 s |
| 差值 = 机动优势 | **3 s** |

**由此定出的 impulse 上限**：3–4 次（按 §8.3 C3 第 4 步）。

## 8.3.12 与候选 A 的取舍记录

| 维度 | 候选 A（运包） | 候选 B（立体双点） |
|---|---|---|
| 骨架 | 新造 | 沿用 CS/瓦 |
| 需要新系统 | 扛包状态、投掷、交接 | 破坏（位图 + 事件） |
| 地图需求 | 运送路线 | 多层 + 可破坏入口 |
| 垂直设计价值 | 低（路线是平面的） | **高**（破坏是垂直维度的核心） |
| 风险 | 容易变成夺旗 | 破坏失衡 |
| 单人可完成度 | 中 | **高**（破坏系统约 2 周，见 8.3.8） |

**结论**：选 B。A 的「扛包」是一整套新状态机 + 新动画 + 新 UI，而 B 只需要一个位图和 20 行 trace 改动，却能换来垂直维度的全部价值。
