# ADR 0007 · 许可边界与净室实现（GPL 绕行）

- 日期：2026-10-24 · S65
- 状态：**已定**
- 关联：契约 M6 §4 D5、`docs/assets-licenses.md`、铁律 K、M6.10（后坐力）/ M6.11（表现层）

## 背景

枪感要"仿 TacZ"，而 M6 的参考清单里还有 OpenArena / Quake3e（GPLv2）、Xonotic（GPLv3）、
Red Eclipse 2（zlib），TacZ 本体是 **GPL-3.0 代码 + CC BY-NC-ND 资产**。
直接抄代码、抄数值或搬资产，任意一条都会把仓库拖进 GPL（或 NC-ND 的限制），
而本项目不打算开源。所以要把"读什么、抄什么、怎么证"写成规则，而不是每人事到临头再判断。

## 决定

1. **不复制、不链接、不逐行改写任何 GPL/AGPL 代码**；GPL 文件不进仓库（包括"只放在注释里"）。
2. **事实可以读，表达不许抄**。允许读 GPL 源确认"一把 COD 式枪需要哪些参数、后坐力表怎么组织"
   这类**事实与方法**；实现按本项目自己写的规格从零写。读过的文件登记在
   `docs/assets-licenses.md` 的「只读参考」表里——把不可验证的"我没看过"换成可审计的记录。
3. **数值自己推导**。计划书 §6.2 已写明不要抄 TacZ 数值（60 tick + 手柄 + 强辅助瞄准，
   我们是 64 tick + 键鼠 + 无辅助）。任何"看起来像"的数值都要能说出推导。
4. **资产单列一条线**：CC0 / CC-BY 才能进构建；CC BY-NC-ND（TacZ 的模型与贴图）**永不进仓库**，
   占位几何体也不例外。
5. **净室流程**（以后凡是"要像 X"的功能）：
   a. 先写行为规格（输入、状态、输出、边界），只描述"看到什么"；
   b. 规格进 `docs/decisions/` 或契约任务；
   c. 写代码时**不再打开**那份 GPL 源，只按规格实现；
   d. 判据写成能红的闸门——证明行为，不证明"像某段代码"。
6. **"仿 TacZ 的手感" = 仿结构**：移动状态 × 距离系数的扩散矩阵、按状态配置的后坐力、
   拔枪/收枪/冲刺后延迟、弹匣与换弹节奏。这些是方法；字段名、表结构、数值全部自己定。

## 后果

- 加一把枪 = `weapons.toml` 里加一段（`--test-weapons` 的
  "a new gun is one new section, no code change" 钉住这条）。
- M6.10 的后坐力表、M6.11 的曳光/开镜按 §5 的规格推进，数值来源写进 PROGRESS。
- `tools/check_sources.ps1` 扫到 GPL/AGPL 头就红：贴进来当场失败，不靠人记得。

## 被否掉的方案

| 方案 | 为什么不行 |
|---|---|
| 直接移植 TacZ 的 `GunData` / 后坐力表 | GPL 传染；且 Java+Forge 生命周期（计划书 §2.2 已否决） |
| 用 GPL 代码"改到不像" | 衍生作品仍是衍生作品 |
| 把 GPL 文件放进仓库但"不编译" | 分发即传染；仓库本身就是分发 |
| 声明"我没看过那份代码" | 不可验证。改为记录读过什么、取的是哪条事实 |
| 抄 OpenArena 的 `bg_weapons.c` 写法 | GPLv2；hitscan + 扩散锥是通用方法，自己实现即可 |
