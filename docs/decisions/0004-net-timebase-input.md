# ADR 0004 — 网络时间轴与输入去重

- 日期：2026-10-19
- 状态：已实现（v0.3 §7.0 + v0.4 §5.2/§5.3）
- 上游：docs/计划书_v0.3.md §7.0/§7.9；docs/网络层深化_v0.4.md §5

## 决定

| 项 | 值 |
|---|---|
| 客户端时间轴 | 服务器 tick + **lead 4**（单程 30 ms ≈ 2 tick + 2 tick 前瞻） |
| 命令盖戳 | `cmd.tick = ServerClock::command_tick()`，每本地步进 +1 |
| 初始化 | 客户端预跑 4 个空 tick，复刻服务器在首个命令到达前的状态 |
| 输入窗口 | 只接受 `[last_executed+1, last_executed+8]`；8 位 seen 位图 |
| 重复输入 | `tick <= last_executed` 或位图命中 → 丢弃；重复包只计数、不记日志 |
| 迟到输入 | 丢弃，**不补执行、不当最新输入重放**；客户端已预测，下次快照回正 |
| 队列长度 | > 4 tick 丢最旧（计划书 §7.9 的病态网络阈值） |
| 旧快照 | 比历史最早预测还旧 → 直接忽略，禁止倒着 snap |

## 为什么 lead 是 4

单程 30 ms = 1.92 tick，取 2；再加 2 tick 前瞻（v0.3 §7.0 允许 1–2）。
命令在 tick T−4 发出、T−2 左右到达，服务器执行 T 时已在队列里。
lead 再大只会增加服务器侧输入延迟，不改善收敛。

## 为什么迟到输入必须丢弃

旧实现把迟到命令赋给 `last_input`，等于让服务端输入流整体晚 2 tick。
客户端每 tick 都预测「当前输入」，服务端每 tick 都执行「上一输入」→ 每 tick 不一致。
实测 30% 丢包场景回滚 1428/2000。改为丢弃后降到 185。

## 证据

- `--test-net` 30% 丢包 + 30 ms + 10 ms 抖动，2000 tick：回滚 185，偏差 0.00000 m。
- N3：5% 丢包 + 30 ms + 10 ms 抖动，60 s（3840 tick）：位置修正 0 次，单次最大 0 m。
- InputWindow 单测：accept / duplicate / late / far / executed-duplicate / overflow / depth=4。

## 未决

- 真实 UDP 下 RTT 抖动更大，lead 可能需要按 RTT 动态调整；v0.1 固定 4。
- 服务器时钟漂移（房主切窗口）后的追赶策略尚未实现（v0.3 §7.0 的「最多丢 2 个 cmd」）。
